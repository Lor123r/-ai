# 0001 需要区分环境的参数设为必填，让遗漏变成编译错误

## 现象

`src/main/storage/portable.ts` 的 `isPackaged` 参数曾经硬编码为 `false`。

单元测试全绿——因为测试环境本来就不是打包环境，`false` 恰好是对的。
真机上永远走默认目录，便携模式从未生效过，而且**没有任何报错**。

## 根因

可选参数 + 默认值 = 遗漏时静默走错分支。

更隐蔽的是：**测试环境恰好掩盖了它**。测试跑在开发环境，`isPackaged` 的真实值就是
`false`，所以硬编码与正确实现的行为完全一致。测试通过不是"证明对了"，
只是"证明在测试环境里对了"。

## 结论

**凡是需要区分环境的参数，一律设为必填，让遗漏变成编译错误。**

判定方式：如果某个参数在测试环境与生产环境取值不同，它就不能有默认值。
有默认值意味着"忘记传"是一个合法状态，而忘记传恰恰是最容易发生的事。

## 反例

不要为了"方便调用方"给环境相关参数设默认值：

```ts
// 错：忘记传就静默走错分支
function resolveDataDir(isPackaged = false) { ... }

// 对：忘记传直接编译失败
function resolveDataDir(isPackaged: boolean) { ... }
```

"方便调用方"在这里是伪需求——调用方只有一个，而静默错误会一直存在。
