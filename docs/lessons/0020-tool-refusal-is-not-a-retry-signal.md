# 0020 工具的「无变化」是结论，不是失败，不要重试

## 现象

一次改 CSS 的任务里，AI 对同一个 `.book-card__remove` 代码块连续调用了约 20 次
编辑工具，每次传入的 `old_str` 与 `new_str` **内容完全相同**。工具每次都如实返回：

```
No changes made: old_str and new_str are the same
```

AI 把这个返回当成"这次没成功"，于是原样重试。中间穿插了十几次
`node -e` 打印该代码块，每次打印出来的内容都一模一样，AI 看完继续重试。
直到用户直接问「你是不是陷入了循环？」才停下。

**这个代码块从头到尾就不需要修改。** 想做的重排早在循环开始前就完成了。

## 根因

**把"工具没有产生变化"误读成"工具调用失败"。** 这两件事的处置方式相反：

| 返回 | 含义 | 正确处置 |
| --- | --- | --- |
| 报错（找不到 `old_str`、权限不足） | 调用失败 | 修正参数后重试 |
| `No changes made: ... are the same` | 调用成功，但无事可做 | **停止**，去确认目标状态 |

重试的隐含前提是"这次失败是暂时的，再来一次可能成功"。但
`old_str === new_str` 是**确定性**的：同样的输入永远得到同样的返回，
重试一万次也不会变。**确定性失败不能靠重试解决，只能靠改变输入或改变目标。**

更深一层：AI 在循环里其实一直在收集"证据"（反复打印代码块），
但**没有把证据拿去和预期比对**。打印出来的内容每次都相同，这本身就是
"目标状态已达成"的证明，却被当成了"还没看清，再看一遍"。
**收集证据而不消费证据，是循环的燃料。**

## 结论

**工具返回"无变化"时，先确认目标状态，再决定是否继续——不要原样重试。**

可判定的做法：

1. **同一个 `old_str`/`new_str` 组合最多尝试一次。** 第二次调用前必须先
   用只读手段（`node -e` 打印、`git diff`、`view`）确认当前状态。
2. **只读输出必须与预期比对，而不是只打印。** 打印完要回答一句
   "这符合预期吗？"——符合就停，不符合才改参数。
3. **连续两次得到相同返回时强制换策略。** 换参数、换工具、或直接问用户。
   不允许第三次用同样的输入。
4. **循环的止损点是用户，不是自己。** 本次是用户发现的。AI 应当自己
   在第二次相同返回时就停下——判据是"返回内容是否与上次逐字相同"。

## 反例

不要这样：

```
edit(old_str=A, new_str=A)  → "No changes made: ... are the same"
edit(old_str=A, new_str=A)  → "No changes made: ... are the same"
edit(old_str=A, new_str=A)  → "No changes made: ... are the same"
...  ← 输入没变，返回必然不变，重试没有信息量
```

也不要"打印了就算查过了"：

```
node -e "打印代码块"   → 内容与上次完全相同
node -e "打印代码块"   → 内容与上次完全相同
...  ← 证据已经足够，缺的是拿它下结论
```

要这样：

```
edit(old_str=A, new_str=A)  → "No changes made: ... are the same"
node -e "打印代码块"        → 确认 A 已在位
→ 结论：目标状态已达成，停止。这个块不需要改。
```

也不要因为"已经试了很多次"就继续试——**沉没成本不是继续的理由**，
恰恰相反，重复次数越多越说明当前策略无效。
