# 0008 单一门禁命令，降低执行偏差

## 现象

本仓库 `package.json` 定义了：

```
npm run verify  =  npm run typecheck && npm run test && npm run test:e2e
```

`AGENTS.md` 明确写：**不接受"单测过了就行"**——typecheck 与 E2E 同样是门禁的一部分，
任何一项红都算没做完。

## 根因

如果门禁是三条独立命令，执行者（尤其是 AI）会倾向于只跑最快的那条。

单测最快，于是"单测过了"被当成"做完了"；typecheck 慢一点，跳过；
E2E 最慢，几乎不会主动跑。结果是**交付时才发现类型错误或集成问题**，
而那时改动已经堆了很多，定位成本成倍上升。

## 结论

**把全部门禁合成一条命令，并明确声明"任何一项红都算没做完"。**

判定方式：**如果存在一条"跑了它就算验证过了"的命令，门禁就是合格的。**
如果需要记住三条命令、并自己判断该跑哪条，门禁就是不合格的。

配套要求：
- 命令名要短且语义明确（`verify` 比 `check:all:strict` 好）
- 文档里只提这一条，不要列出分解步骤（否则又变成多命令）
- 明确写出"部分通过不算通过"

## 反例

不要把门禁拆成需要人判断的组合：

```json
// 错：执行者会挑最快的跑
"scripts": {
  "typecheck": "...",
  "test": "...",
  "test:e2e": "..."
}

// 对：一条命令覆盖全部
"scripts": {
  "verify": "npm run typecheck && npm run test && npm run test:e2e"
}
```

也不要在文档里写"至少跑一下单测"——"至少"就是给跳过留了口子。
