# 0011 想让 AI 主动做的事，必须给出可对照的触发条件

## 现象

本仓库建好了经验库 `docs/lessons/`，`AGENTS.md` 里也写了：

> 踩到新坑时追加一条，编号只增不改。

结果：**经验库建好之后，再也没有新增过条目。**

同样的写法还有"主动补测试""主动更新文档""主动报告风险"——
写进规则了，但都不会发生。

## 根因

"踩到新坑"**不可判定**。

AI 无法回答"我这次算不算踩到新坑"，于是默认答案永远是"不算"。
这不是偷懒，是缺少判断依据：没有可对照的事件，就没有触发点。

对比一下可判定的规则长什么样：

| 不可判定 | 可判定 |
| --- | --- |
| 踩到新坑时记一条 | 第一次尝试的修法是错的，且换了另一种才通过 |
| 重要改动要补测试 | 新增了 `src/core/` 下的导出函数 |
| 保持文档同步 | 改了 `src/shared/ipc.ts` 的频道常量 |

右列的共同点：**能事后对照**——发生了某个具体事件，而不是"觉得重要"。

还有第二个原因：**没有写明"不满足就别写"**。
只给正向条件时，AI 会倾向于"多写点总没错"，产出凑数条目，
反而让索引变长、真正有用的条目被淹没。

## 结论

**凡是希望 AI 主动做的事，都要写成"满足任意一条就做"的事件清单，并明确写出"不满足就别做"。**

判定方式：**把规则念一遍，问"AI 怎么知道自己这次该不该做？"**
答不上来（或答案是"看情况"），这条规则就不会被执行。

本仓库的落地写法（`AGENTS.md` 的「什么时候必须追加一条」）：

```markdown
满足**任意一条**就要追加，不要等别人提醒：

1. 你修掉了一个 bug，而**第一次尝试的修法是错的**。
2. 你发现某处代码/文档的写法**与直觉相反**，且不写下来下一个人还会踩。
3. 你因为**缺少某条信息**而做错了事。
4. 门禁红了，而红的原因**不是本次改动引入的**。

不满足以上任意一条时**不要写**。
```

配套：**不要用门禁强制**。该不该记是判断题，机器判不了；
硬判只会逼出凑数条目。规则给 AI 判断依据，门禁给机器硬性检查，两者分工不同。

## 反例

```markdown
<!-- 错：不可判定，永远不会触发 -->
踩到新坑时追加一条经验。
重要改动记得补测试。
保持文档与代码同步。

<!-- 错：只给正向条件，会催生凑数条目 -->
尽量多记录经验，越多越好。
```

也不要把这类规则做成门禁检查（例如"每次提交必须新增一条经验"）——
那会产出大量"本次改动无特殊经验"之类的填充条目，把经验库变成噪音。
