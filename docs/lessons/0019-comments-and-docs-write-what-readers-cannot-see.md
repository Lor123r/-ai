# 0019 注释与文档只写读者看不出来的东西

## 现象

本仓库的注释密度明显高于同类项目，但读起来不累。对比两类注释：

```ts
// 低信息量：读者看代码就知道
// 遍历所有注解

// 高信息量：读者看代码看不出来
// 顺序是承重的：必须先重定向再按 id 去重，否则同一本书的注解
// 会因为 bookId 不同而被当成两条，去重失效，上报的计数会偏大。
```

文档侧同理：`README.md` 第 14 章明确列出当前限制，并逐条标注是
"还没做"还是"刻意不做"；而 `README.md` 本身有 139.8 KB、14 章，
AI 无法一次装载，只能先 grep 找标题再分段读。

## 根因

**"是什么"能从代码读出来，写它等于重复一遍代码，还会随代码改动而过期。
"为什么"读不出来——它来自当时的权衡、踩过的坑、以及不能动的边界。**

对 AI 而言这个区别更关键：AI 读代码的能力很强，不需要人告诉它"这里在遍历"；
它真正需要的是"这里不能改"和"改了会怎样"。

文档侧有两个独立的失效模式：

1. **AI 会把"没做"当成"做漏了"。** 看到"书架排序不持久化"，AI 很可能热心地
   去加持久化——但作者是**刻意**不做的。AI 不知道理由，就会把设计决策
   当成缺陷去"修复"，引入作者不想要的复杂度。
2. **巨型文档无法按需读取。** 文档是给读者消费的接口，而 AI 的上下文是有限资源。
   想要第 7 章的一个细节却必须面对整个 139.8 KB，代价是上下文被挤占。

## 结论

**注释与文档都只写读者看不出来的东西。**

**注释**：写为什么这么选、换序/换值会坏什么、当初踩过什么坑。
判定方式：**把注释删掉，如果读者会自然地写出错误的代码，这条注释就是必要的；
如果读者照样能写对，这条注释就是噪音。**

具体该写的内容：
- 承重约束（见 0003）
- 反直觉的选择（"这里故意不传 recursive"）
- 失败模式（"失败时回滚内存，调用方可以当成没发生过"）
- 被否决的方案及原因（"不用 X，因为 Y"）

**文档的限制清单**：每条限制都要标注"还没做"还是"刻意不做"。
判定方式：**如果一条限制被删掉，AI 会不会去实现它？会的话，就必须写清理由。**
写法：限制 + 理由 +（可选）如果要做的话方向是什么。

**文档的规模**：超过一定规模就拆分，入口文件只做索引。
判定方式：**如果读者无法在一次读取中拿到需要的内容，文档就该拆了。**
经验阈值：单文件超过约 30–50 KB 就该考虑拆分。
本仓库的 `docs/lessons/` 就是这个原则的应用——一条经验一个文件，
AI 可以只读相关的那几条，而不是装载整个经验库。

## 反例

不要写复述代码的注释，也不要写会过期的注释：

```ts
// 错：复述代码
// 把 fontSize 写进样式
themes.override('font-size', `${settings.fontSize}px`, true)

// 对：解释为什么必须带 !important
// 一律带 !important：书内 CSS 常常自带 font-size 与颜色，不加优先级会盖不住。
themes.override('font-size', `${settings.fontSize}px`, true)
```

也不要写"TODO: 以后优化"这类没有约束力的注释——要么写清为什么现在不做，
要么就别写。

不要只列限制不写理由：

```markdown
<!-- 错：AI 会当成待办 -->
## 已知限制
- 书架排序不持久化
- 没有全文搜索

<!-- 对：说清是刻意取舍 -->
## 已知限制
- 书架排序/筛选不持久化。**刻意**：这是"这次想怎么看"，不是内容，
  下次打开回到默认更符合预期。
- 没有全文搜索。**还没做**：EPUB 可先做章节内搜索，TXT 直接字符串匹配。
```

也不要为了显得完整而隐藏限制——隐藏的代价是 AI 会重新踩一遍同样的坑。

不要把"内容全"当成优点而拒绝拆分：

```markdown
<!-- 错：139.8 KB 单文件，AI 读不进来 -->
README.md  ← 架构 + 数据模型 + 13 个流程 + IPC 契约 + 测试地图 + 迭代历史 + ...

<!-- 对：入口做索引，各章独立 -->
README.md          ← 概览 + 链接
docs/architecture.md
docs/data-model.md
docs/flows.md
docs/ipc.md
docs/testing.md
```

也不要拆得过碎——一个概念一个文件会让读者在文件间反复跳转。
按"读者会想一次读完的范围"来切。
